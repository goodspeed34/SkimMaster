# SkimMaster web panel UI and UX audit

**Baseline:** `e93e0e6`. **Scope:** the shipped first-run wizard and all 22 panel destinations, including receiver and decoder configuration, live monitoring, statistics, reporting, and station maintenance.

The most urgent problems affect ordinary operation. The panel requires horizontal scrolling even for basic setup at narrow widths. Live pages reload while operators are editing forms. The spectrum can display historical IQ under a live-sounding source label, and its tuning control requires a pointer. Several failure and maintenance flows take the operator away from the panel at the point where they need to recover or verify the result.

## Evidence and severity

The browser review used the compiled server, headless Firefox 158 on Linux, a disposable loopback station, a stereo IQ WAV fixture, and seeded reception and noise data. It covered all navigation destinations at desktop size, a narrow viewport, keyboard focus, successful setup and IQ capture testing, chart interactions, refresh behavior, invalid TOML, and snapshot download. Source review followed the rendered HTML, scripts, styles, and route handlers for the remaining states. The linked design assets are inputs to the live build. [Asset build](../src/web/assets/embed.py#L225)

**Browser** marks a finding reproduced in the running panel or measured in its DOM. **Source** marks a finding traced to the implementation. **P1** means a blocked core task, loss of work, or a misleading state that can lead to an incorrect action. **P2** means meaningful friction, ambiguity, or reduced access with a workaround. **P3** means a smaller clarity or polish issue. Physical radios, real reporting endpoints, native mobile browsers, and screen-reader speech were outside the test environment. The repository's 25 tests passed, including the panel, receiver emulators, and disposable restore and reset tests.

## Shared navigation and accessibility

| ID | Severity | Weakness and impact | Recommended change |
| --- | --- | --- | --- |
| UI-01 | P1 · Browser | The panel and wizard are at least 1,080 CSS pixels wide. In a 390-pixel browser frame with 386 pixels of content width, the panel content starts at x=190 and the wizard starts at x=150. The right edge of Next is at x=907, so operators must pan sideways to reach fields and advance. The wizard also lacks a viewport declaration, so real mobile browsers can scale the page down. Fixed navigation and help columns consume 430 pixels before content. [Panel CSS](../ReferenceDesign/style.css#L7) · [Wizard shell](../ReferenceDesign/wizard.html#L1) | Reflow the shell and wizard at narrow widths, make help collapsible, and confine horizontal scrolling to data tables that need it. Verify at 320 and 390 CSS pixels and with zoom. |
| UI-02 | P1 · Browser | The panel has a main landmark but its page title is a styled `div`. The shared menu is an `aside` with no navigation landmark or skip link. A keyboard user encounters the persistent menu before the task on every page. Wizard step changes leave focus on Next, and the numbered steps convey current state visually. [Shell](../ReferenceDesign/index.html#L61) · [Generated title](../src/web/assets/embed.py#L230) · [Wizard navigation](../src/web/assets/wizard.js#L42) | Add a skip link, a named navigation landmark and real headings. Mark the current wizard step programmatically and move focus to the step heading when advancing or going back. |
| UI-03 | P1 · Browser | Visible labels are disconnected from controls in the decoder settings, recording uploader, noise controls, activity controls, and snapshot uploader. Examples include the CW low-frequency setting, the WAV file input, and the smoothing selector. Generic chart canvases also have no accessible data summary. [Analysis controls](../src/web/assets/panel.html#L3) · [Decoder forms](../src/web/assets/panel.html#L309) · [Restore form](../src/web/assets/panel.html#L190) | Associate visible labels, units and help with each field. Give charts a named equivalent and expose important values as text or a table. |
| UI-04 | P2 · Browser | The dense 12-pixel base text, 11-pixel help text, compact buttons and fixed sidebars make primary actions hard to distinguish from secondary actions. Multiple row actions reuse names such as Edit, Delete and Configure without including the target in the accessible name. [Shared styles](../ReferenceDesign/style.css#L221) · [Receiver actions](../src/web/assets/receiver_editor.html#L6) · [Summary actions](../src/web/assets/panel.html#L85) | Establish a visible primary action on each workflow, enlarge touch targets, and name row actions with the receiver, schedule or service they affect. Preserve a compact view for operators who want higher data density. |
| UI-05 | P2 · Source | Several state-changing routes return plain text on failure, including token expiry, spectrum tuning and decoder settings. A conflict after another tab saves gives the operator a reload instruction but no structured way to keep and reapply edits. Receiver and schedule forms retain some submitted values yet keep the stale revision on a failed save. [Form validation](../src/web/common.cpp#L349) · [Receiver retry](../src/web/receivers.cpp#L139) · [Schedule retry](../src/web/schedules.cpp#L101) · [Decoder save](../src/web/decoders.cpp#L216) | Keep errors on the originating page, preserve entered values, associate validation with fields, and offer a conflict recovery path that loads current settings before applying edits. |

## Suggested repair order

1. Fix form stability and recovery. Remove whole-page refresh from interactive views, give pause immediate effect, and retain inputs and focus through validation failures and conflicts.
2. Make first-run and spectrum operation dependable. Add IQ verification and a post-setup status handoff, then require fresh source context and provide keyboard tuning.
3. Reflow the shared shell and repair semantics across pages. Prioritize the wizard, key monitoring pages and maintenance. Check at narrow widths, with keyboard alone and with a screen reader.
4. Improve operational interpretation and recovery. Clarify live versus playback, time and metric units, feed status and backup scope. Then improve browse, search and export controls across historical views.
